# 节点类型与关系类型

## 节点类型

| 节点类型 | 英文名称 | 定义 | 字段 | 示例 | 用途 |
|---|---|---|---|---|---|
| 学科 | Discipline | 组织领域来源与研究传统。 | id,label,definition,evidence | Human-Robot Interaction | 用于建立领域边界与检索入口。 |
| 概念 | Concept | 可被定义、比较和连接的核心术语。 | definition,parent,related_nodes | Trust Calibration | 适合 RAG 查询与主题索引。 |
| 理论 | Theory | 解释交互现象的抽象模型。 | claim,scope,limitations,evidence | Situated Action | 用于支撑设计推论。 |
| 方法 | Method | 研究、设计或评估的方法。 | stage,procedure,pros,limits | Wizard-of-Oz | 用于推荐研究方案。 |
| 技术 | Technology | 机器人或界面系统模块。 | capability,constraints,design_risk | AR Interface | 用于把工程能力转成交互问题。 |
| 交互模态 | Interaction Modality | 输入输出通道与反馈形式。 | input,feedback,context | Voice Interaction | 用于多模态组合。 |
| 机器人类型 | Robot Type | 按形态、任务或场景划分的机器人。 | embodiment,tasks,risks | Service Robot | 用于场景化设计。 |
| 应用场景 | Scenario | 机器人运行的真实环境和服务情境。 | users,tasks,constraints | Hospital Guidance | 用于作品集 brief。 |
| 任务 | Task | 目标、步骤、责任与失败点。 | goal,subtasks,handoff | Medication Delivery | 用于任务流和评估设计。 |
| 用户群体 | User Group | 具有特定能力、需求和风险的使用者。 | needs,abilities,risks | Older Adults | 用于用户研究。 |
| 设计问题 | Design Issue | 可被设计介入的痛点或张力。 | problem,cause,impact | Unclear Robot Intent | 用于机会生成。 |
| 评估指标 | Evaluation Metric | 衡量交互结果的变量。 | measure,tool,scenario | Trust | 用于实验和可用性研究。 |
| 文献来源 | Paper / Source | 支持事实或理论的论文、标准或网页。 | authors,year,venue,url | Goodrich & Schultz 2007 | 用于证据追踪。 |
| 案例或产品 | Case / Product | 真实或研究原型案例。 | context,features,lessons | Hotel Delivery Robot | 用于案例研究。 |
| 设计机会 | Design Opportunity | 可发展为项目或原型的方向。 | users,scenario,prototype,metrics | AR Path Guidance | 用于作品集与 poster。 |
| 研究问题 | Research Question | 可被方法和数据回答的问题。 | theme,method,data,contribution | How does robot transparency affect trust? | 用于论文和 poster。 |

## is_part_of
- 中文解释：属于
- 使用场景：层级、模块、主题从属关系。
- 示例三元组：
  - Shared Autonomy -- is_part_of --> Robot Autonomy
  - concept_shared_autonomy -- is_part_of --> concept_robot_autonomy
  - Shared Autonomy -- is_part_of --> Robot Autonomy

## related_to
- 中文解释：相关
- 使用场景：弱关系或横向主题连接。
- 示例三元组：
  - HRI -- related_to --> Human Factors
  - discipline_hri -- related_to --> discipline_hci
  - discipline_hri -- related_to --> discipline_robotics

## enables
- 中文解释：使能
- 使用场景：技术或方法让某种交互成为可能。
- 示例三元组：
  - AR Interface -- enables --> Spatial Robot Guidance
  - tech_motion_planning -- enables --> concept_legible_motion
  - tech_ar_mr_interface -- enables --> modality_visual_ar

## constrains
- 中文解释：约束
- 使用场景：安全、场景、能力限制设计空间。
- 示例三元组：
  - Safety Requirement -- constrains --> Robot Motion
  - Safety Requirement -- constrains --> Robot Motion
  - Safety Requirement -- constrains --> Robot Motion

## improves
- 中文解释：改善
- 使用场景：设计策略提升体验或指标。
- 示例三元组：
  - Robot Transparency -- improves --> Trust Calibration
  - concept_shared_autonomy -- improves --> concept_human_agency
  - concept_transparency -- improves --> concept_trust_calibration

## evaluated_by
- 中文解释：被评估
- 使用场景：主题、原型或指标之间的评估关系。
- 示例三元组：
  - Service Robot Prototype -- evaluated_by --> Usability Testing
  - scenario_hotel_delivery -- evaluated_by --> metric_trust
  - scenario_elderly_care -- evaluated_by --> metric_acceptance

## used_in
- 中文解释：用于
- 使用场景：方法、技术或概念被应用到场景。
- 示例三元组：
  - Wizard-of-Oz -- used_in --> Social Robot Prototyping
  - tech_ar_mr_interface -- used_in --> scenario_industrial_assembly
  - tech_ar_mr_interface -- used_in --> scenario_public_cleaning

## depends_on
- 中文解释：依赖
- 使用场景：能力或体验依赖某系统模块。
- 示例三元组：
  - Shared Autonomy -- depends_on --> Intention Recognition
  - concept_shared_autonomy -- depends_on --> tech_intention_recognition
  - tech_llm_agent_layer -- depends_on --> concept_affordance

## conflicts_with
- 中文解释：冲突
- 使用场景：目标、指标或策略之间存在张力。
- 示例三元组：
  - High Autonomy -- conflicts_with --> User Control
  - concept_robot_autonomy -- conflicts_with --> concept_human_agency
  - High Autonomy -- conflicts_with --> User Control

## derived_from
- 中文解释：源自
- 使用场景：概念或机会由文献、方法、图谱路径推导。
- 示例三元组：
  - Trust Calibration -- derived_from --> Trust in Automation
  - concept_embodied_interaction -- derived_from --> theory_situated_action
  - concept_robot_autonomy -- derived_from --> theory_levels_automation

## applied_to
- 中文解释：应用到
- 使用场景：理论或方法应用到具体对象。
- 示例三元组：
  - Situated Action -- applied_to --> Service Robot Workflow
  - concept_intelligent_interaction_design -- applied_to --> discipline_hri
  - theory_situated_action -- applied_to --> scenario_hotel_delivery

## measured_by
- 中文解释：由……测量
- 使用场景：指标与量表、日志或行为数据连接。
- 示例三元组：
  - Workload -- measured_by --> NASA-TLX
  - modality_visual_ar -- measured_by --> metric_situation_awareness
  - concept_anthropomorphism -- measured_by --> metric_social_presence

## designed_for
- 中文解释：为……设计
- 使用场景：机会、界面或机器人面向目标用户。
- 示例三元组：
  - Hospital Guidance Robot -- designed_for --> Patients
  - Hospital Guidance Robot -- designed_for --> Patients
  - Hospital Guidance Robot -- designed_for --> Patients

## supports
- 中文解释：支持
- 使用场景：节点促进流程、目标或研究输出。
- 示例三元组：
  - Knowledge Graph -- supports --> Design Opportunity Discovery
  - concept_explainability -- supports --> concept_transparency
  - method_research_through_design -- supports --> opportunity_ar_path_guidance

## challenges
- 中文解释：挑战
- 使用场景：技术或场景引出设计困难。
- 示例三元组：
  - LLM Agent -- challenges --> Accountability
  - tech_llm_agent_layer -- challenges --> concept_explainability
  - tech_perception -- challenges --> concept_transparency

## requires
- 中文解释：需要
- 使用场景：任务或评估对条件提出要求。
- 示例三元组：
  - Collaborative Assembly -- requires --> Human Safety
  - robot_cobot -- requires --> metric_safety
  - scenario_industrial_assembly -- requires --> concept_legible_motion

## influences
- 中文解释：影响
- 使用场景：变量之间存在影响但方向强度需研究确认。
- 示例三元组：
  - Robot Autonomy -- influences --> Human Trust
  - concept_robot_autonomy -- influences --> metric_trust
  - concept_explainability -- influences --> metric_trust

## mediates
- 中文解释：中介
- 使用场景：一个节点作为关系中介。
- 示例三元组：
  - Interface Transparency -- mediates --> Autonomy and Trust
  - Interface Transparency -- mediates --> Autonomy and Trust
  - Interface Transparency -- mediates --> Autonomy and Trust

## extends
- 中文解释：扩展
- 使用场景：新主题扩展旧理论或框架。
- 示例三元组：
  - GraphRAG -- extends --> RAG
  - concept_intelligent_interaction_design -- extends --> discipline_hci
  - discipline_embodied_ai -- extends --> discipline_robotics
