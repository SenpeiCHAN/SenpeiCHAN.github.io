# 智能交互设计 × 机器人：面向 HRI 设计研究的知识图谱框架

## 摘要

[Fact] Human-Robot Interaction / 人机机器人交互已经形成跨 robotics、HCI、human factors、AI、工程与社会行为科学的研究共同体，ACM/IEEE HRI 官方说明也强调其跨学科属性 [S23](https://humanrobotinteraction.org/2026/)。机器人正在进入制造、服务、医疗、家庭和公共空间，IFR World Robotics 报告提供了全球机器人市场统计入口 [S26](https://ifr.org/worldrobotics/)。

[Explanation] 对智能交互设计而言，机器人不是“带屏幕的产品”，而是会移动、感知、决策、失败并影响人类安全与责任感的具身系统。本研究把 HRI 视为设计研究、机器人系统、人因评估与知识图谱建模的交叉领域。

[Inference] 如果把机器人技术模块转换为可查询的知识节点和关系，设计师就可以从“感知、导航、自主性、解释、反馈、场景、评估指标”之间发现设计机会，而不是只做形式或 UI 包装。

[Design Implication] 本文档包建立一个中文研究报告、知识图谱 ontology、节点/关系 schema、表格数据、三元组、JSON 示例和作品集/Poster 转化模板，用于后续 RAG / GraphRAG、作品集项目和论文选题生成。

## 关键词

Human-Robot Interaction / 人机机器人交互；Intelligent Interaction Design / 智能交互设计；Embodied AI / 具身智能；Embodied Interaction / 具身交互；Social Robotics / 社交机器人；Collaborative Robots / 协作机器人；AR/MR Interfaces / 增强与混合现实界面；Trust Calibration / 信任校准；Research through Design / 通过设计进行研究；Knowledge Graph / 知识图谱。

## 研究背景

[Fact] HRI 经典综述 Goodrich & Schultz 将该领域组织为人与机器人之间感知、行动、任务、角色和系统评估的综合问题 [S01](https://doi.org/10.1561/1100000005)。社会机器人综述则强调，当社会互动本身成为机器人功能的一部分时，设计者需要考虑表达、人格、社会规范和长期影响 [S02](https://doi.org/10.1016/S0921-8890(02)00372-X)。

[Explanation] 智能交互设计介入机器人时，核心不是“让机器人更像人”，而是让人的意图、机器人能力、场景约束和风险边界能够互相理解。服务机器人需要服务蓝图；协作机器人需要安全和可读运动；社交机器人需要拟人化边界；LLM 机器人需要 grounding、解释和责任链。

[Fact] 信任是 HRI 的核心评价变量之一。Hancock 等人的元分析把人、机器人和环境因素纳入 HRI 信任研究 [S05](https://doi.org/10.1177/0018720811417254)；Lee & See 则从自动化角度强调“适当依赖”而非单纯提高信任 [S06](https://doi.org/10.1518/hfes.46.1.50_30392)。

[Design Implication] 因此，本课题以“设计研究型知识操作系统”为目标：让概念能被查询，关系能被追溯，机会能被推导，评估能被设计进项目。

## 核心研究问题

1. 智能交互设计如何介入机器人系统，而不是停留在视觉或外观层？
2. HRI 中哪些理论、方法和评估指标最值得设计学生优先掌握？
3. 感知、导航、规划、自主性、失败恢复等机器人模块如何转化为交互设计问题？
4. 如何建立一个能被 LLM/RAG/GraphRAG 复用的 HRI 知识图谱？
5. AR/MR、多模态反馈和可解释界面如何改善机器人意图理解与情境感知？
6. 机器人自主性如何影响信任、控制感、责任归属和安全体验？
7. 如何从图谱路径中生成作品集项目、conference poster 和论文雏形？

## 研究目标

- 建立一个面向 HRI 设计研究的领域知识框架。
- 建立顶层 ontology、节点类型、关系类型和机器可读 JSON schema。
- 建立方法与评估指标系统，支撑后续实验和作品集叙事。
- 建立设计机会库和研究问题库。
- 建立可进入 RAG / GraphRAG 的来源、三元组和样例知识图谱。

## 研究范围与边界

### 纳入内容

HRI、HCI、机器人交互、服务机器人、社交机器人、协作机器人、多模态交互、AR/MR 机器人界面、机器人自主性、共享自主性、远程操作、信任与可解释性、设计研究方法、HRI 评估方法、AI agent/LLM 与机器人中间层。

### 排除内容

过于底层的控制算法推导、与交互体验无关的机械结构细节、纯 AI 模型训练细节、与人机交互无关的工业自动化流程、未能转化为人类理解/控制/安全/体验问题的技术细节。

## 方法

本研究采用文献综述、关键词检索、主题编码、本体构建、知识图谱建模、设计机会推导和作品集转化。外部来源包括 ACM/IEEE HRI、CHI、ACM THRI、Human Factors、International Journal of Social Robotics、IEEE/ISO/IFR 官方资料和 arXiv/PMLR 中与 LLM robotics 相关的前沿文献；所有已使用来源见 `appendix/来源与检索记录.md`。

## 核心本体框架

本图谱采用 10 个一级本体：Human、Robot、Interaction、Intelligence、Embodiment、Interface、Context、Task、Evaluation、Ethics & Society。它们共同形成一个从人类行动者到机器人系统、从场景任务到评估伦理的设计研究闭环。

## Human / 人
- 定义：HRI 中的人不是抽象用户，而是有身体能力、认知负荷、情绪、经验、责任和社会角色的行动者。
- 关键子类：User Group, Ability, Mental Model, Trust, Emotion, Agency, Expertise
- 与其他本体的关系：Human 执行 Task、感知 Robot、通过 Interface 与 Robot 协作，并受 Context 与 Ethics 约束。
- 对设计研究的意义：把用户研究从偏好收集推进到能力、风险、角色和长期关系的建模。
- 典型研究问题：人如何理解机器人意图？人何时希望接管？不同用户如何校准信任？
- 典型应用场景：医院导诊、老年陪护、工业协作、公共空间服务。
- 可延伸作品集方向：以特定用户群体为中心的服务机器人体验系统。

## Robot / 机器人
- 定义：机器人是能感知、决策并在物理世界行动的具身系统；其交互体验受硬件形态、传感器、控制和安全策略共同塑造。
- 关键子类：Service Robot, Social Robot, Cobot, Mobile Manipulator, Telepresence Robot, Medical Robot
- 与其他本体的关系：Robot 承载 Intelligence 与 Embodiment，通过 Interface 反馈状态，在 Context 中执行 Task。
- 对设计研究的意义：把技术模块翻译成用户可理解、可预测、可协作的行为。
- 典型研究问题：机器人应显露哪些状态？何时表达不确定性？不同形态如何影响社会期待？
- 典型应用场景：酒店配送、病房物流、工位协作、家庭助理。
- 可延伸作品集方向：机器人状态表达、失败恢复或意图可视化原型。

## Interaction / 交互
- 定义：交互是人和机器人围绕任务、环境与社会意义进行的连续协调，不只是一条输入-输出通道。
- 关键子类：Command, Feedback, Turn-taking, Handover, Coordination, Repair, Negotiation
- 与其他本体的关系：Interaction 连接 Human 与 Robot，并由 Interface、Context、Task、Evaluation 共同定义。
- 对设计研究的意义：重点从界面控件转向协作节奏、可见状态、互相适应和失败修复。
- 典型研究问题：机器人如何请求澄清？人如何知道机器人下一步？交互失败怎样不破坏信任？
- 典型应用场景：人机交接、协作装配、公共空间避让、远程操作。
- 可延伸作品集方向：多模态交互流程与可测试原型。

## Intelligence / 智能
- 定义：智能包括感知、识别、推理、规划、学习、解释和自主性；在 HRI 中必须被人理解和约束。
- 关键子类：Perception, Intention Recognition, Planning, Autonomy, LLM Agent, Explainability
- 与其他本体的关系：Intelligence enables Robot action, but constrains Human trust when opaque or unstable.
- 对设计研究的意义：把算法能力转成可控、可解释、可协商的交互体验。
- 典型研究问题：LLM agent 如何作为机器人中间层？智能系统如何表达置信度和失败原因？
- 典型应用场景：自然语言任务规划、共享自主、开放场景服务。
- 可延伸作品集方向：AI agent + robot 任务协商界面。

## Embodiment / 具身
- 定义：具身强调身体、动作、空间和环境不是交互背景，而是认知与协作的组成部分。
- 关键子类：Body, Motion, Spatial Presence, Affordance, Materiality, Physical Feedback
- 与其他本体的关系：Embodiment mediates Interaction and shapes Human mental models.
- 对设计研究的意义：关注路径、姿态、速度、距离、接触和物理可供性如何传达意义。
- 典型研究问题：机器人运动怎样表达意图？身体形态会引发哪些错误期待？
- 典型应用场景：移动导览、机械臂协作、康复训练、家庭空间移动。
- 可延伸作品集方向：具身状态表达与空间交互研究。

## Interface / 界面
- 定义：界面是人与机器人系统交换意图、状态、解释和控制权的媒介，可以是屏幕、语音、手势、AR/MR、触觉或物理形态本身。
- 关键子类：Voice UI, Gesture UI, Gaze UI, Haptic UI, Tangible UI, AR/MR UI, Status Display
- 与其他本体的关系：Interface enables Interaction and mediates Intelligence legibility.
- 对设计研究的意义：界面要降低不确定性、展示状态边界，并支持不同用户的控制与恢复策略。
- 典型研究问题：哪种模态最适合低负荷场景？AR/MR 能否提升路径和意图理解？
- 典型应用场景：协作机器人路径提示、服务机器人状态显示、远程操作反馈。
- 可延伸作品集方向：AR/MR 机器人路径与意图可视化界面。

## Context / 场景
- 定义：场景包括物理空间、组织流程、社会规范、风险水平和时间节奏，是机器人交互成立的条件。
- 关键子类：Home, Hospital, Hotel, Factory, Public Space, Museum, School
- 与其他本体的关系：Context constrains Task, Interface, Safety, Ethics and Evaluation.
- 对设计研究的意义：同一个机器人能力在不同场景中会变成不同交互问题。
- 典型研究问题：公共空间机器人如何遵守隐性社会规范？医院机器人如何与护理流程共存？
- 典型应用场景：医院、酒店、工厂、社区、博物馆、机场。
- 可延伸作品集方向：基于服务蓝图的场景化机器人体验设计。

## Task / 任务
- 定义：任务是人机协作的目标结构，包括目标、子任务、责任、风险、时序和交接点。
- 关键子类：Delivery, Guidance, Handover, Assembly, Monitoring, Rehabilitation, Cleaning
- 与其他本体的关系：Task requires Robot capability, Human role allocation, Interface support and Evaluation criteria.
- 对设计研究的意义：任务建模把机器人能力转译为交互流程和原型范围。
- 典型研究问题：哪些步骤应自动化？哪些步骤必须保留人类决策？任务失败后怎样恢复？
- 典型应用场景：物品递送、协作装配、导览、远程巡检。
- 可延伸作品集方向：任务流、控制权转移和失败恢复设计。

## Evaluation / 评估
- 定义：评估用于判断机器人交互是否可用、可信、安全、可接受、低负荷且能长期融入场景。
- 关键子类：Usability, Trust, Workload, Acceptance, Safety, Situation Awareness, Social Presence
- 与其他本体的关系：Evaluation measures Interaction outcomes and informs design iteration.
- 对设计研究的意义：把作品集从“做了一个原型”推进到“有研究问题、测量方案和证据”。
- 典型研究问题：用什么指标证明 AR 路径提示有效？如何测量信任校准而不是单纯信任高低？
- 典型应用场景：Wizard-of-Oz 实验、可用性测试、长期部署、控制实验。
- 可延伸作品集方向：带有评估矩阵的 HRI 设计研究项目。

## Ethics & Society / 伦理与社会
- 定义：伦理与社会层关注隐私、安全、责任归属、偏见、可访问性、劳动影响和社会规范。
- 关键子类：Privacy, Accountability, Bias, Accessibility, Labor, Consent, Norms
- 与其他本体的关系：Ethics constrains Intelligence, Data, Context and deployment decisions.
- 对设计研究的意义：要求设计不仅提升效率，还要明确边界、告知、同意、责任与脆弱群体保护。
- 典型研究问题：服务机器人收集哪些数据？LLM 机器人误导用户时谁负责？机器人是否加剧不平等？
- 典型应用场景：养老、医疗、公共空间、教育、家庭。
- 可延伸作品集方向：机器人伦理交互准则与设计审计工具。


## 关键知识判断

### 判断 1：机器人交互不是普通界面交互的延伸，而是具身行动系统的协作问题

[Fact] Dourish 的 embodied interaction 强调行动和情境在交互中的基础地位 [S16](https://mitpress.mit.edu/9780262541787/where-the-action-is/)；Suchman 的 situated action 批评把行动理解为计划的直接执行 [S17](https://dl.acm.org/doi/abs/10.5555/38407)。

[Inference] 机器人在真实空间中行动，因此设计对象不只是屏幕，而包括路径、速度、姿态、距离、接触、失败和接管。

[Design Implication] 作品集应展示“机器人系统模块 × 用户理解 × 场景流程 × 评估指标”的映射，而不是只展示一个 app 界面。

### 判断 2：自主性需要被设计为可协商的角色分配

[Fact] Parasuraman 等提出自动化可以分布在信息获取、分析、决策和行动等不同功能中 [S07](https://doi.org/10.1109/3468.844354)；Beer 等进一步面向 HRI 讨论机器人自主性等级 [S09](https://doi.org/10.5898/JHRI.3.2.Beer)。

[Explanation] 自主性不是越高越好。它会改变人类控制感、责任归属和信任校准。

[Design Implication] 设计机会包括可调自主性面板、接管机制、任务确认、计划预览和失败转人工。

### 判断 3：信任设计的目标是校准，而不是“让用户更相信机器人”

[Fact] HRI 信任元分析说明信任受机器人、人和环境因素共同影响 [S05](https://doi.org/10.1177/0018720811417254)；自动化信任研究强调 appropriate reliance / 适当依赖 [S06](https://doi.org/10.1518/hfes.46.1.50_30392)。

[Inference] 机器人如果表现得过于自信，可能制造过度信任；如果状态不透明，又可能导致用户拒绝使用。

[Design Implication] 关键设计变量是透明性、解释粒度、置信度表达、失败恢复和用户接管。

### 判断 4：AR/MR 是机器人意图可视化的重要界面层

[Fact] Walker 等对 VAM-HRI 建立了虚拟设计元素分类 [S12](https://doi.org/10.1145/3597623)；Milgram 与 Kishino 的 mixed reality taxonomy 是 MR 研究基础 [S30](https://globals.ieice.org/en_transactions/information/10.1587/e77-d_12_1321/_p)。

[Inference] AR/MR 的设计价值不是炫技，而是把机器人不可见的路径、目标、安全区和不确定性变成可理解线索。

[Design Implication] 可发展为 AR 路径提示、安全区可视化、远程操作状态叠加、协作机械臂动作预览。

### 判断 5：LLM agent 能扩展机器人交互，但必须被 grounding、安全和责任链约束

[Fact] SayCan 把语言模型建议与机器人可供性/value functions 结合 [S27](https://arxiv.org/abs/2204.01691)；PaLM-E 和 RT-2 代表了具身多模态和 VLA 方向 [S28](https://arxiv.org/abs/2303.03378) [S29](https://proceedings.mlr.press/v229/zitkovich23a.html)。

[Inference] LLM 可以成为“任务协商中间层”，但语言能力不等于物理可执行能力。

[Design Implication] 需要设计可执行性检查、计划预览、用户确认、风险提示、失败解释和日志追溯。

## 设计转化框架

`文献证据 -> 概念节点 -> 关系路径 -> 场景约束 -> 设计问题 -> 原型方向 -> 评估指标 -> 作品集/论文输出`

示例路径：

`Robot Autonomy -> influences -> Trust -> measured_by -> Trust Questionnaire -> applied_to -> Hotel Delivery Robot -> derived_from -> Failure Recovery Design`

这条路径可以生成一个作品集项目：酒店配送机器人失败恢复体验系统；也可以生成研究问题：失败解释粒度是否影响用户再次使用意愿？

## 结论

这个知识图谱的核心贡献，是把“智能交互设计 × 机器人”从资料汇总转化为可查询、可扩展、可复用、可设计转化的研究系统。它能帮助设计学生建立 HRI 系统理解，把机器人技术模块转译为交互问题，并把研究证据连接到作品集、poster、论文和个人 AI 研究助手。
