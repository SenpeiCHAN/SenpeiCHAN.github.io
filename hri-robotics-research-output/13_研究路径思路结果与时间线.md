# 基于主研究报告的后续研究路径、思路、阶段结果与时间线

## 1. 研究定位

本研究不是继续扩写一篇普通综述，而是把《智能交互设计 × 机器人：面向 HRI 设计研究的知识图谱框架》推进成一个可执行的研究系统。核心目标是：

- 把 HRI / Robotics / HCI / Design Research 的知识组织成可检索、可扩展的结构。
- 把机器人技术模块转译为设计问题、交互机会和评估指标。
- 把研究报告、知识图谱、作品集项目、poster 选题和 LLM/RAG 复用连接起来。

当前研究采用的基本判断是：

1. 机器人不是普通界面终端，而是会在真实空间中行动的具身系统。
2. 智能交互设计的任务不是给机器人“加 UI”，而是设计人、AI、机器人、场景和责任之间的协作关系。
3. 知识图谱的价值不在于画概念图，而在于让“来源、概念、关系、设计机会、评估指标”可以互相追溯。

## 2. 研究路径总览

本研究建议按照 7 条连续路径推进：

| 阶段 | 研究路径 | 核心问题 | 方法 | 主要产出 |
|---|---|---|---|---|
| P0 | 问题界定 | 这个课题到底研究什么、不研究什么？ | scope statement、纳入/排除标准 | 领域边界、关键词、研究问题 |
| P1 | 文献基础 | 哪些理论和综述构成最低知识底座？ | 文献综述、来源分级、主题编码 | 核心文献表、主题证据链 |
| P2 | 本体建模 | 领域中的一级类目、节点和关系如何组织？ | ontology、taxonomy、schema 设计 | 10 个顶层本体、节点类型、关系类型 |
| P3 | 双视角映射 | 机器人系统模块如何转化为交互设计问题？ | system mapping、design translation | 机器人系统视角、交互设计视角 |
| P4 | 方法与评估 | 如何证明一个 HRI 设计项目有研究价值？ | 方法矩阵、指标矩阵 | 研究方法表、评估指标表 |
| P5 | 设计机会生成 | 哪些方向能转化为作品集、poster 或论文？ | graph path reasoning、opportunity framing | 设计机会库、研究问题库 |
| P6 | 原型与验证 | 哪个问题值得做成可测试原型？ | Wizard-of-Oz、原型测试、对比实验 | 原型、实验方案、初步数据 |
| P7 | 知识库复用 | 如何让大模型复用这套知识？ | RAG、GraphRAG、节点维护 | 可检索知识库、研究助手 |

## 3. 研究思路

### 3.1 从“领域综述”转向“知识操作系统”

普通综述通常按文献或主题排列。本研究采用“知识操作系统”思路：每个重要知识都需要回答以下问题：

- 它是什么概念？
- 它属于哪个上位领域？
- 它和哪些概念发生关系？
- 它由哪些来源支持？
- 它能转化成什么设计问题？
- 它可以用哪些方法研究？
- 它可以被哪些指标评估？
- 它能否进入作品集、poster、论文或 LLM 知识库？

因此，研究对象不是单篇论文，而是 `Source -> Concept -> Relation -> Scenario -> Design Issue -> Prototype -> Metric` 这条链路。

### 3.2 从“机器人技术”转向“人能否理解、控制和信任”

主报告已经确定，机器人系统至少包含感知、导航、环境理解、意图识别、决策、动作执行、运动规划、安全、反馈、表达、失败恢复、可解释性、自主性和人类介入。

研究重点不是深入推导控制算法，而是追问：

- 感知错误如何被用户发现？
- 导航路径如何让路人理解？
- 规划结果如何解释？
- 自主性如何影响控制感？
- 失败时如何恢复信任？
- 安全约束如何被可视化？

这个转译过程是智能交互设计介入机器人研究的核心。

### 3.3 从“高信任”转向“信任校准”

信任不是越高越好。Hancock 等关于 HRI 信任的元分析说明，信任受人、机器人和环境因素共同影响；Lee & See 对自动化信任的研究强调 appropriate reliance / 适当依赖，而不是无条件依赖。对应来源见 [S05](appendix/来源与检索记录.md#s05-a-meta-analysis-of-factors-affecting-trust-in-human-robot-interaction) 和 [S06](appendix/来源与检索记录.md#s06-trust-in-automation-designing-for-appropriate-reliance)。

因此后续研究应避免提出“如何提升用户信任机器人”这种过宽问题，改为：

- 如何让用户知道机器人何时可靠、何时不可靠？
- 解释粒度如何影响接管意愿？
- 失败恢复是否能修复被破坏的信任？
- 自主性等级如何影响责任归属？

### 3.4 从“可视化界面”转向“不可见状态的可理解化”

AR/MR、状态灯、声音、触觉和动作表达的价值，不是增加视觉层，而是让用户理解机器人不可见的内部状态：

- 下一步路径
- 当前任务
- 目标对象
- 传感器是否看见人
- 是否正在等待
- 为什么失败
- 哪些区域危险
- 什么时候可以接管

VAM-HRI survey 为 AR/MR 机器人界面提供了分类基础，见 [S12](appendix/来源与检索记录.md#s12-virtual-augmented-and-mixed-reality-for-human-robot-interaction-a-survey-and-virtual-design-element-taxonomy)。Dragan 等对 legibility / predictability 的区分可用于运动意图设计，见 [S13](appendix/来源与检索记录.md#s13-legibility-and-predictability-of-robot-motion)。

### 3.5 从“LLM 控制机器人”转向“LLM 作为任务协商中间层”

LLM robotics 方向可以作为未来扩展，但需要严格标注成熟度。SayCan、PaLM-E、RT-2 等工作说明语言、视觉和动作之间正在建立新的连接，但语言模型能生成计划不等于机器人一定能执行。相关来源见 [S27](appendix/来源与检索记录.md#s27-do-as-i-can-not-as-i-say-grounding-language-in-robotic-affordances)、[S28](appendix/来源与检索记录.md#s28-palm-e-an-embodied-multimodal-language-model)、[S29](appendix/来源与检索记录.md#s29-rt-2-vision-language-action-models-transfer-web-knowledge-to-robotic-control)。

更可行的设计研究切口是：

- LLM 如何把用户意图转化为可确认任务？
- 系统如何说明“这个任务当前不能做”？
- 用户如何查看、修改或取消机器人计划？
- AI agent、机器人和人之间的责任如何被记录？

### 4.2 已得到的核心研究结论

1. **HRI 是智能交互设计进入机器人领域的主入口。**  
   Goodrich & Schultz 的 HRI survey 和 ACM/IEEE HRI 的会议定位说明，该领域天然连接机器人学、HCI、人因工程和 AI。对应来源见 [S01](appendix/来源与检索记录.md#s01-human-robot-interaction-a-survey)、[S23](appendix/来源与检索记录.md#s23-acmieee-international-conference-on-human-robot-interaction-2026)。

2. **机器人交互的核心问题是具身协作，而不是屏幕操作。**  
   Dourish 的 embodied interaction 和 Suchman 的 situated action 支持将行动、情境和环境纳入交互理解。对应来源见 [S16](appendix/来源与检索记录.md#s16-where-the-action-is-the-foundations-of-embodied-interaction)、[S17](appendix/来源与检索记录.md#s17-plans-and-situated-actions-the-problem-of-human-machine-communication)。

3. **自主性应被设计为角色和责任分配。**  
   Parasuraman 等的 automation model 与 Beer 等的 robot autonomy framework 说明，自主性可以拆分到不同功能和等级。对应来源见 [S07](appendix/来源与检索记录.md#s07-a-model-for-types-and-levels-of-human-interaction-with-automation)、[S09](appendix/来源与检索记录.md#s09-toward-a-framework-for-levels-of-robot-autonomy-in-human-robot-interaction)。

4. **信任研究应关注 calibration。**  
   HRI 设计中更有价值的问题是“适当依赖”，而不是“让用户尽可能相信机器人”。对应来源见 [S05](appendix/来源与检索记录.md#s05-a-meta-analysis-of-factors-affecting-trust-in-human-robot-interaction)、[S06](appendix/来源与检索记录.md#s06-trust-in-automation-designing-for-appropriate-reliance)。

5. **AR/MR 与多模态反馈适合解决机器人状态不可见问题。**  
   AR/MR 可以把路径、目标、安全区、计划和风险转成用户可理解的空间信息。对应来源见 [S12](appendix/来源与检索记录.md#s12-virtual-augmented-and-mixed-reality-for-human-robot-interaction-a-survey-and-virtual-design-element-taxonomy)、[S30](appendix/来源与检索记录.md#s30-a-taxonomy-of-mixed-reality-visual-displays)。

6. **设计研究可以成为 HRI 知识生产方式。**  
   Zimmerman 等和 Gaver 对 Research through Design 的讨论，为作品集型研究提供方法基础。对应来源见 [S14](appendix/来源与检索记录.md#s14-research-through-design-as-a-method-for-interaction-design-research-in-hci)、[S15](appendix/来源与检索记录.md#s15-what-should-we-expect-from-research-through-design)。

## 7. 推荐先做的 3 个研究方向

### 方向 A：AR/MR 机器人路径与意图可视化

- 研究问题：AR 路径提示是否提升用户对移动机器人意图的理解？
- 核心知识节点：AR/MR Interface、Legible Motion、Situation Awareness、Safety。
- 方法：comparative study + prototype testing。
- 指标：目标推断准确率、NASA-TLX、感知安全。
- 适合产出：作品集主项目、conference poster。
- 风险：需要控制 AR 信息量，避免视觉遮挡和认知负荷上升。

### 方向 B：服务机器人失败恢复体验系统

- 研究问题：失败解释粒度如何影响用户信任校准和再次使用意愿？
- 核心知识节点：Failure Recovery、Service Robot、Trust Calibration、Service Blueprint。
- 方法：Wizard-of-Oz + 场景化问卷 + 服务蓝图。
- 指标：信任变化、错误恢复时间、用户满意度。
- 适合产出：服务设计型作品集、中文研究报告章节。
- 风险：需要明确失败类型，例如导航失败、无法识别、配送延迟、任务取消。

### 方向 C：LLM 机器人任务协商中间层

- 研究问题：LLM agent 作为机器人中间层会提升还是削弱用户控制感？
- 核心知识节点：LLM Agent Layer、Affordance、Shared Autonomy、Explainability、Accountability。
- 方法：对话原型 + 可执行性反馈测试。
- 指标：控制感、任务理解、接管意愿、错误恢复。
- 适合产出：前沿方向 brief、AI + robotics portfolio project。
- 风险：容易过度技术化；必须把重点放在人如何理解、确认和修改机器人计划。

## 8. 后续资料组织方式

建议每新增一篇文献，都按以下结构记录：

```text
Source -> 研究主题 -> 方法 -> 关键发现 -> 可进入节点 -> 可新增关系 -> 设计启发 -> 可评估指标
```

建议每新增一个设计机会，都按以下结构记录：

```text
Scenario -> User Group -> Robot Type -> Design Issue -> Related Concepts -> Prototype -> Metric -> Source
```

建议每新增一个研究问题，都按以下结构记录：

```text
Relation Path -> Research Question -> Independent Variable -> Dependent Variable -> Method -> Data -> Contribution
```

## 9. 下一步执行清单

1. 在 20 个设计机会中选择 1 个主项目和 1 个备选项目。
2. 为主项目补充 8-12 篇针对性文献，不再泛泛扩大 HRI 总范围。
3. 为主项目建立一个独立子图谱：至少 20 个节点、30 条关系、30 条三元组。
4. 选择 1 个原型形式：AR mockup、Figma 流程、Wizard-of-Oz 对话、服务蓝图或实体交互草模。
5. 选择 2-3 个指标，不要一次性评估所有指标。
6. 做 3-5 人预测试，记录理解错误、信任变化、操作负荷和反馈意见。
7. 把预测试结果回写到知识图谱，形成 evidence node 或 design principle。

## 10. 当前结论

基于主研究报告，后续研究应从“完整领域覆盖”转为“选择一个可验证切口”。最推荐的切口是：

- AR/MR 机器人路径与意图可视化；
- 服务机器人失败恢复体验；
- LLM 机器人任务协商中间层。

这三个方向都能同时满足四个条件：有文献基础、有交互设计空间、有可做原型、有可测评估指标。下一阶段的关键不是继续扩写概念，而是选定一个方向，建立子图谱并做小规模原型验证。
